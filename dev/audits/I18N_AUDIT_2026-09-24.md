# I18N audit: user-visible text that does not come from the locale file
**Updated:** 2026-09-24 · **Version:** v3.14.419

Written before translation into Hawaiian (`haw.json`) starts, so the translator
is not handed a file that cannot reach part of the interface. FROZEN: stamped
with the version it was written against.

## 1. Method

| layer | how it was read | reach |
|---|---|---|
| static shell (`LingCoT.html` outside `<script>`) | parsed as HTML (parse5); every text node and every `title`, `placeholder`, `aria-label`, `alt` checked for a `data-i18n*` marker on the element or an ancestor | complete for markup |
| rendered views (inline script and `source/modules/*.js`) | parsed as JavaScript (acorn); every template literal scanned as HTML with `${…}` held as a gap, so a tag spanning an expression is still a tag; string literals checked where they reach the screen (`textContent`, `title`, `placeholder`, `alert`/`confirm`, markup strings, label-like table values, `+` concatenation) | good; object maps with arbitrary keys needed a second, manual pass (§2.3) |
| Python host (`LingCoT.pyw`) | every string returned to the page, and every window or dialog title | complete |
| bundled resources | each prose field in `pos_tags`, `type_choices`, `dep_relations`, `leipzig_glosses`, `selection_relations`, `selection_templates` checked for its locale key | complete |
| fonts | `NotoSans-Regular.ttf` cmap checked for ʻokina (U+02BB) and the ten kahakō vowels | complete |

`en.json` at v3.14.418: 1,181 keys.

## 3. Out of scope, stated so it is a decision rather than an omission

| what | why not now |
|---|---|
| log lines | developer-facing; `log_triage.js` matches on their text |
| error detail from the JS engine or the OS (`{err}`) | embedded in a translated sentence; the detail stays as the system produced it |
| CLI and setup scripts (`setup.py`, `build_env.py`, `corpus_*.py`) | a tester runs setup once, from `setup.md`, which is English |
| exported documents (`dict_export.py` PDF, LaTeX) | the export's language is a separate question from the interface's: a Hawaiian interface may still export an English dictionary |
| annotation data, language names typed by the user | data, not interface |

## 4. For the translator

- 32 of 1,181 values carry an English plural pattern such as `word(s)`; rephrase
  freely, the placeholders `{n}` are what the code relies on.
- 151 values contain placeholders (`{n}`, `{loc}`, …). They must survive
  translation unchanged; the key-parity guard planned with `haw.json` should
  check placeholders as well as keys.
- R6 is the one place the code passes an English word into a sentence; it moves
  to two keys, singular and plural, like `copy.btn` / `copy.btn_1`.

## 5. What follows

All of §2 moves into `en.json` in the tester build's `tb-strings` step, and a
guard keeps it that way: the scanner behind this audit, run by the suite, fails
on any new user-visible literal. Plan: `dev/DEV_PLAN.md` §1, *Tester's build*.
